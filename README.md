# cappv1 — PPTX Alt-Text Automation

Drop PowerPoint files into `input/`, run one command, get the same files back in `output/` — same filename — with accessibility alt-text automatically written onto every meaningful image. Captions are generated by a vision-capable LLM via [OpenRouter](https://openrouter.ai), using each slide's title/body/notes as context so the description fits *why the image is there*, not just what's in it.

## Features

- **One command**: `cappv1 start` — no manual Python/venv steps.
- **Chunked, resumable**: processes one slide at a time and checkpoints after each, so a crash or interruption picks up where it left off instead of restarting the deck.
- **Smart filtering**: skips tiny icons/dividers automatically, detects and reuses captions for repeated images (logos), and lets the model itself flag genuinely decorative images — no wasted API calls.
- **Self-healing**: if a file's output goes missing after being marked complete, the next run detects the drift and reprocesses it (reusing cached captions, no extra cost) instead of silently doing nothing.
- **Fail-fast on unrecoverable errors**: billing (402) and auth (401/403) errors fail immediately with an actionable message, instead of burning retries on something retrying can't fix.
- **Live, colored progress**: `cappv1 start` runs in the background and auto-attaches a live colorized view with a per-slide progress bar — `Ctrl+C` stops watching, not the job.
- **Free-tier friendly**: `cappv1 models` lists free vision-capable models currently on OpenRouter and switches with one keystroke.

## Requirements

- macOS/Linux with `bash`, `python3` (3.11+)
- An [OpenRouter](https://openrouter.ai) account and API key

## Setup

1. Put your key in `.env` (already gitignored):
   ```
   OPENROUTER_API_KEY=sk-or-v1-...
   ```
2. Symlink the launcher onto your `PATH` (one time):
   ```
   ln -sf "$(pwd)/bin/cappv1" ~/.local/bin/cappv1
   ```
3. Check everything's ready:
   ```
   cappv1 doctor
   ```

`cappv1 start` bootstraps its own Python virtualenv and installs dependencies automatically the first time it runs — no separate install step. You never need to touch Python, virtual environments, or even `cd` into the project folder — `cappv1` handles all of that.

## Quick start walkthrough

### Step 1 — Add your PowerPoint files
Drag and drop, or copy, your `.pptx` file(s) into the project's `input/` folder. Any filename works, and you can drop in one file or many at once — every `.pptx` sitting there gets processed.

> Only `.pptx` works (the modern PowerPoint format). Old `.ppt` files need to be re-saved as `.pptx` from PowerPoint first (File → Save As → PowerPoint Presentation).

### Step 2 — Run it
Open a terminal — from anywhere, no `cd` needed — and type:
```
cappv1 start
```
`start` is required — plain `cappv1` on its own just prints the help/usage text, it won't kick anything off. That's deliberate: typing `cappv1 start` is an unambiguous "yes, go" action.

Here's what you'll see, in color, in this order:

1. A quick health check (fast, no network call):
   ```
   cappv1 doctor - environment check

     [✓] .env file found
     [✓] OPENROUTER_API_KEY is set
     [-] API key live check - skipped (--quick)
     [✓] Python environment ready - installed
     [✓] input/ folder is ready
     [✓] output/ folder is ready

   All checks passed - ready to run. Type: cappv1 start
   ```
2. Confirmation that it's running, detached from your terminal:
   ```
   ✓ cappv1 started in background (pid 20195)
   ```
3. **Live, colored progress**, automatically — you don't need to run a separate `tail` command yourself:
   ```
   Live progress - Ctrl+C stops watching, the job keeps running in the background

   12:55:00 INFO [file: quarterly-review.pptx] starting
   12:55:03 INFO [file: quarterly-review.pptx] [████--------------] 1/12 [section: "Financials"] captioned 2/2 images
   12:55:06 INFO [file: quarterly-review.pptx] [████████-----------] 2/12 [section: "Financials"] skipped 1 decorative image, captioned 1/1
   ...
   ✓ [file: quarterly-review.pptx] saved to output/quarterly-review.pptx
   ```
   The `[████--------------]` bar fills in as it works through the slides. `INFO` lines are colored, and the final "saved to" line for each file turns bold green with a ✓ so completions jump out.

`Ctrl+C` at this point only stops *watching* — the actual processing keeps running in the background even after you disconnect, close the terminal, or the view times out. To check on it again later, just re-tail the log file directly (path is printed if the view doesn't auto-attach in time):
```
tail -f /Users/ssharma33/Desktop/cappv1/logs/run-*.log
```

### Step 3 — Get your finished file
Once you see the green `✓ ... saved to output/...` line, your captioned deck is ready — open it straight from `output/`. The original in `input/` is never touched.

### Step 4 — Spot-check it (recommended)
Right-click an image → **Edit Alt Text**, and confirm the caption reads well. The model is good but not perfect — for anything going to an external audience, a quick human skim is worth it.

## The commands

| Command | What it does |
|---|---|
| `cappv1 start` | Starts processing everything in `input/`, in the background, then shows you live colored progress. This is the one you'll use almost every time. |
| `cappv1 doctor` | Checks your setup — API key (live-verified), Python environment, folders — and prints a colored ✓/✗ report. Safe to run any time, changes nothing. |
| `cappv1 models` | Lists free vision-capable models currently available on OpenRouter and lets you switch to one — the fix for billing errors. |
| `cappv1 clean` | Wipes `input/`, `output/`, and the tracked run history (`.state/`), so you're starting from a totally empty workspace. **Deletes files — see warning below.** |
| `cappv1` (no args) | Prints the usage/help text above. Does not start anything. |

### `cappv1 doctor`
Run this any time something seems off, or just to confirm you're ready before a big batch:
```
cappv1 doctor
```
```
cappv1 doctor - environment check

  [✓] .env file found
  [✓] OPENROUTER_API_KEY is set
  [✓] API key is valid - verified with OpenRouter
  [✓] Python environment ready - installed
  [✓] input/ folder is ready
  [✓] output/ folder is ready

  2 file(s) waiting in input/

```
If something's wrong, each failing line is marked `[✗]` in red with a plain-English reason. `cappv1 start` runs this same check (a faster version, skipping the live API call) before doing anything else — if it fails, it prints the failure and stops, rather than crashing partway through, and tells you to run `cappv1 doctor` for the full picture.

### `cappv1 models` — free models and billing errors
Default is [`minimax/minimax-m3:free`](https://openrouter.ai/minimax/minimax-m3) — vision-capable, free, and tested to produce accurate captions and correctly flag decorative images. Any vision-capable model on OpenRouter works, including paid ones (e.g. `anthropic/claude-sonnet-5`) once your account has credits — set `MODEL=` in `.env` directly, or run `cappv1 models` to pick from the **live** current list without leaving the terminal.

If a caption ever fails with something like `OpenRouter billing error (402) - '...' needs credits`, your current model needs credits you don't have — this is the fix:
```
cappv1 models
```
```

  Current: minimax/minimax-m3:free

   2  google/gemma-4-26b-a4b-it:free - Google: Gemma 4 26B A4B (free)

   4  minimax/minimax-m3:free - MiniMax: MiniMax M3 (free) (current)
   ...

Pick a number, or Enter to keep current:
```
Type a number and hit Enter — it writes the choice straight into `.env` (`MODEL=...`) and you're ready to run `cappv1 start` again. Press Enter with no number to leave things as they are. The list is fetched live from OpenRouter each time, so it always reflects what's actually available — it isn't hardcoded here because free-model availability changes over time.

### `cappv1 clean` ⚠️
```
cappv1 clean
```
```
cappv1 clean

  ✓ removed 3 file(s) from input/
  ✓ removed 3 file(s) from output/
  ✓ cleared 3 tracked run(s) from .state/

Workspace is clean and ready to go - drop files into input/, then run: cappv1 start
```
**This permanently deletes every `.pptx` currently sitting in `input/` and `output/`**, plus their tracked run history — there's no undo. Use it to reset between unrelated batches of decks, not mid-batch. It never touches `logs/`, so your run history there is preserved even after a clean.

## Other ways to run it

`cappv1 start` accepts the same flags as the underlying script, so all of these work:

| What you want | Command |
|---|---|
| Process everything new in `input/` (background + live view) | `cappv1 start` |
| Process just one specific file | `cappv1 start --file "my-deck.pptx"` |
| Pick back up on a file that got interrupted partway | `cappv1 start --resume` |
| Run in the current terminal, no backgrounding (blocks until done) | `/Users/ssharma33/Desktop/cappv1/run.sh` |

**When to use `--resume`:** if the machine slept, lost power, or you killed the process mid-run. The tool checkpoints after every slide, so just running `cappv1 start` again automatically picks up where it left off instead of starting the deck over — you don't lose progress or pay for images already captioned.

## What happens to different kinds of images

You don't need to sort your images beforehand — the tool figures this out automatically per image:

- **Real content** (charts, photos, diagrams, screenshots) → sent to the model, gets a real descriptive caption.
- **Tiny images** (small icons, bullet graphics, dividers — under ~40px) → automatically skipped, no API call spent.
- **Repeated images** (the same logo/icon appearing on multiple slides) → captioned once, then reused everywhere else it appears, so you're not paying to caption the same logo 20 times.
- **Genuinely decorative images** (background textures, purely visual dividers with no informational content) → the model itself recognizes these and marks them as decorative (empty alt-text), which is the correct, accessible thing to do — PowerPoint's own "Mark as Decorative" does the same.

## Configuration

All in `.env`:

| Variable | Default | Meaning |
|---|---|---|
| `OPENROUTER_API_KEY` | *(required)* | Your OpenRouter key |
| `MODEL` | `minimax/minimax-m3:free` | Any vision-capable OpenRouter model ID; change via `cappv1 models` or by hand |
| `CONCURRENCY` | `4` | Max simultaneous caption requests |
| `MIN_IMAGE_SIZE_PX` | `40` | Images smaller than this (either dimension) are treated as decorative, no API call |
| `MAX_ALT_TEXT_CHARS` | `125` | Target max caption length (WCAG-style guidance) |

## Troubleshooting

| Symptom | What's going on | Fix |
|---|---|---|
| `cappv1: command not found` | The `~/.local/bin/cappv1` symlink is missing or `~/.local/bin` isn't on your `PATH` | Run `ln -sf /Users/ssharma33/Desktop/cappv1/bin/cappv1 ~/.local/bin/cappv1`, then open a new terminal |
| Typing `cappv1` alone just prints help and nothing happens | Expected — `start` is required | Type `cappv1 start` |
| `cappv1 start` says "Not ready to run yet" | A quick check failed (usually the API key) | Run `cappv1 doctor` for the full picture and a plain-English reason |
| `No .pptx files in input/ yet` | `input/` is empty — nothing to process | Drop a `.pptx` file into `input/`, then run `cappv1 start` again |
| A file logs `already complete, skipping` (shown dimmed/gray) | The tool already fully processed this file in a previous run | Expected — nothing changed. (If `output/` is missing that file despite this, the tool detects that automatically and reprocesses it for you — no action needed.) To force a full redo anyway, run `cappv1 clean` |
| `caption generation failed permanently` for a specific image (after 3 retries) | The API call failed 3 times in a row (rate limit, network blip, temporary outage) | Alt-text is left blank for that image; just run `cappv1 start` again — it'll retry only what's missing |
| `OpenRouter billing error (402) - needs credits` | Your current model needs credits you don't have (fails instantly, no wasted retries) | Run `cappv1 models` and pick a free one, then `cappv1 start` again |
| `OpenRouter rejected the request (401/403)` | Your API key is invalid or was revoked | Run `cappv1 doctor` — the live key check will confirm and explain |
| A whole file fails and gets skipped | The `.pptx` is corrupted or not a valid PowerPoint file | Re-save the file from PowerPoint and drop it back into `input/` |
| Terminal shows raw codes like `[36m` instead of color | Your terminal/log viewer doesn't interpret ANSI color codes (e.g. some editors, or piping to a file) | View it in a normal terminal with `tail -f`; colors are automatically disabled when output isn't a real terminal |

## How it works

```
input/*.pptx
     │
     ▼
1. Discover   scan input/, skip files already complete (only if output/ actually still has them)
     ▼
2. Parse      open with python-pptx, map PowerPoint "sections" for logging
     ▼
3. Extract    per slide: pull images + slide title/body/notes as context
     ▼
4. Filter     skip tiny/duplicate images (perceptual hash), no API call spent
     ▼
5. Caption    send image + context to the configured model, concurrently (bounded)
     ▼
6. Write-back set alt-text (the descr attribute) directly on the slide XML
     ▼
7. Save + log write output/<same filename>.pptx, checkpoint state, log progress
```

The processing unit is **one slide at a time**, not the whole deck — since sections rarely share images in practice, each slide's captions can be generated independently, and a crash mid-deck only loses the in-progress slide, not the whole file.

**Error handling**: corrupt/unreadable files are skipped (rest of `input/` still processes); a single image's caption failure leaves that image's alt-text blank rather than failing the deck; 429/5xx/network errors retry with backoff (3 attempts), while 402/401/403 fail immediately with an actionable message since retrying can't fix those; state and output are checked for drift on every run so a deleted/moved output file gets regenerated instead of silently skipped forever.

**Invariant**: the only thing this tool ever writes into a `.pptx` is the alt-text field on images — layout, positions, formatting, text, and slide order always come out identical to the input. See **[skills.md](skills.md)** if you're extending this codebase or working on it with an AI agent.

## Project structure

```
cappv1/
├── input/              # drop .pptx files here
├── output/              # captioned .pptx files land here, same filename as input
├── .state/               # per-file progress (json) - enables resume + drift detection
├── .env                   # OPENROUTER_API_KEY=... MODEL=... (gitignored)
├── logs/                   # per-run logs (run-<timestamp>.log) + cappv1-launcher.log
├── bin/
│   └── cappv1                # symlinked onto PATH; subcommand dispatcher (start/doctor/models/clean)
├── run.sh                     # bootstraps .venv, runs python -m src.main
├── requirements.txt
├── README.md                   # this file
├── skills.md                    # guardrail: caption-only, nothing else about the pptx changes
├── github-repo.md                # repo name/description/topics for GitHub
├── TODO-security.md               # deferred findings + patches from the pre-release security review
└── src/
    ├── main.py                 # CLI entrypoint (--file, --resume)
    ├── config.py                # .env loading
    ├── pipeline.py                # discover -> parse -> caption -> write -> save, logging/colors
    ├── pptx_reader.py              # python-pptx wrapper: slides, sections, images, alt-text r/w
    ├── image_filter.py             # decorative/tiny/duplicate detection
    ├── llm_client.py                # OpenRouter API client, retry/fail-fast logic
    ├── state.py                      # per-file progress tracking
    ├── doctor.py                      # `cappv1 doctor` - stdlib-only, works before .venv exists
    └── models.py                      # `cappv1 models` - stdlib-only free-model picker
```

## Roadmap (v2 — not yet built)

- **Bring-your-own-key for other providers**: direct Anthropic (Claude) API key, OpenAI, DeepSeek — as alternatives to routing everything through OpenRouter.
- **Offline/local model support**: caption via a locally-hosted vision model (e.g. Ollama), no internet or API key required.
- Batch multiple images from the same slide into a single LLM call to cut request count further.
- Optional human-review step: dump a CSV/HTML of `slide → image → generated caption` for spot-checking before trusting `output/` wholesale.
- `.ppt` (legacy binary format) support via a LibreOffice conversion pass.
